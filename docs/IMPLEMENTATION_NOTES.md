## 采用的工程选择

1. **集合冲突**：原文式 (13) 的 `A={i:gate_i=1}` 可能与已有 R 重叠，而式 (3) 要求二者互斥。本实现给予恢复集合优先级：`A=hard_active & ~R_previous`。恢复后的行为在本次请求后续轮次持续保留，不再次压缩。
2. **情景边界**：只合并原始索引连续的非活动行为；遇到活动行为形成的间隔就拆分，每组最多 `episode_size` 项。论文未指定分组长度，默认 8 是工程设定。
3. **推理状态**：`h0=Linear(target)`。每轮把上一轮状态作为最后一个读出 token，使用 causal attention，并从其输出得到新状态。pre/post 两个分支均使用同一个 `h_previous`，符合式 (27)，不把 pre 状态当作 post 分支的初始状态。
4. **行为编码**：Tiny 使用稳定 SHA-256 token hashing + 训练词嵌入均值；HF 使用同一 LLM 输入词嵌入均值。两者均为行为级向量，不提供图片编码或逐 BPE token 的 KV 路由。用户历史内部顺序通过路由索引维护；拼接顺序依原文采用 target、active、memory、restored，而不是全部按原始时间混排。
5. **压缩器**：`Linear(3D,D) → GELU → Linear(D,D)`。论文未指定 φ 网络结构。
6. **软硬门训练**：前向使用硬决策，并将已选中向量乘直通门；预算长度使用硬值加软梯度。可变长索引选取与情景分组本身不可导，因此这种局部直通近似不是对所有可能分区的精确梯度。未选中的活动分支没有完整的反事实任务梯度；路由器主要通过已选分支、压缩权重与预算获得梯度。
7. **恢复门梯度**：选中的原始向量乘恢复直通门，未恢复记忆乘其补门；恢复损失中的 any-open 指示采用 `1-prod(1-rho)` 的软替代梯度。恢复阈值的前向逻辑保持硬决策。这是原文未规定的工程补充，梯度有偏，可能对初始化和参数敏感。全不恢复时没有完整的反事实恢复效果监督；需要实际训练验证控制器是否学到有效策略。
8. **教师**：复用模型参数和完整历史，使用 no-grad 输出；学生保留梯度。训练时 HF LoRA dropout 仍按配置启用，因此教师与学生可能有随机性；Tiny dropout 为 0。没有额外教师预热阶段。
9. **计数与预算**：上下文计数不包含 target 与最后的状态读出 token。损失中的 `budget_length` 在前向等于原文恢复前的 hard count，反向只近似活动门，情景数量视为常数。B 使用 `budget_ratio * N`，不整数取整。恢复后的长度另行报告，预算不保证严格满足。
10. **执行与成本**：每个轮次运行一次恢复前推理；有恢复时再运行一次 post 推理。没有恢复时复用 pre 输出。所有历史嵌入保留，尚无 CPU/offload、KV 缓存分页或跨请求记忆持久化；不要将行为上下文缩短比例直接视为端到端加速比例。

## 数值处理

- 标准差采用总体标准差 `unbiased=False`，避免 N=1 的 NaN。
- cosine similarity 采用 epsilon；概率使用 log-softmax 计算。
- 无压缩记忆时，记忆损失返回可微的零；无恢复时恢复损失前向为零。
- 恢复时删除对应压缩记忆，原始行为不会与该记忆重复进入 post 上下文。
- 空历史显式报错；输入数据脚本跳过尚无正反馈历史的请求。
